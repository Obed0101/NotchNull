# NotchNull 1.5.4

## Clearer usage budgets

- Show actual reset times separately from forecasts, a ten-cell usage bar and the remaining daily budget.
- Learn hourly consumption from quota readings stored locally for up to 28 days. Until each hour has at least three hours of observations on three different dates, show that the schedule is being learned instead of predicting exhaustion from a short burst.
- Forecasts are estimates, not provider warnings. Offline gaps and stale readings are not treated as zero usage, and no additional provider requests are made.

## Installed agents and the Agents panel

- Show Claude Code, Codex and opencode blocks, settings groups, permissions rows
  and agent skill rows only when that agent is actually installed. Detection
  reads the executable or the agent's own data directory; leftover NotchNull
  hooks, settings and skill links do not count as an installation.
- Add a Cleanup group in Settings › Agents for a Claude hook or opencode plugin
  left behind by an agent that is no longer installed, and let Settings › Build
  remove a dangling agent-skill link.
- Keep the Agents tab available with no agent installed. It becomes an empty
  state naming what to install; hiding the tab still works through
  Settings › Tabs & Wings.
- Top-align both Agents tab columns and fit the open panel to the taller column.
  The configured panel height becomes a maximum for the Agents tab, and taller
  content still scrolls.

## Notch activity rendering

- Replace the animated rolling time labels with one shared one-second clock and
  fixed-width, unanimated text. SwiftUI no longer runs a numeric transition into
  every tick, which used to keep the display link busy for as long as an agent
  activity or timer was visible.
- Rasterize the notch chrome that does not change between ticks, so a label tick
  redraws the label instead of rebuilding the body fill and emission edge.
- Pause the clock, the chase outline and the agent mark timeline when the notch
  is hidden, covered by a fullscreen app or on a sleeping display. Visible notch
  windows on several displays share the same tick.

A 1.5.0 build sustained 37–56% of one core with a live agent activity, and 1.5.2
still recorded about 23%. After this change the settled notch no longer runs a
display-link loop between ticks: the recurring cost is one label redraw per
second, and the main-thread CoreAnimation flush that dominated the samples is
gone.

## OpenCode monitor

- Stop the opencode monitor from reparsing the day's assistant messages on
  every two-second poll. It now keeps one read-only SQLite connection, compares
  `PRAGMA data_version` and a database/WAL stat fingerprint, and reuses the last
  snapshot when nothing changed.
- Run token aggregation only while the Agents tab is visible. Opening the tab
  establishes a baseline; new messages use an incremental cursor; a full
  reconciliation runs at most once per sixty seconds to correct edits, deletes
  and same-millisecond inserts. The closed notch reads session state only.
- Use one SQLite JSON1 aggregate for totals, output, message count and hourly
  buckets instead of transferring message bodies into Swift. The previous Swift
  parser remains as the fallback when JSON1 or a payload shape is unsupported.
- Report the current local day's tokens from messages created today instead of
  the cumulative `session_v2` columns. On the reference database the old path
  showed 419.71M tokens for today versus 389.66M for today's 1,674 messages; the
  corrected total removes that 30.05M overcount. The earlier reference reading
  in the proposal was 363.99M versus 333.94M, with the same 30.05M gap.
- Refresh session state immediately on `/opencode` plugin events and app
  activation without waiting for the next two-second poll. Missing, locked or
  malformed sources keep the last known totals and report usage unavailable
  until a later scan succeeds.

Measured on this Mac with the notch closed and the app settled, `top` reported
8.0–8.9% of one core for the previous build and 0.4–0.5% for this build. A
five-second `sample` of the new build showed only session-state checks on
`dev.notchnull.opencode` and no message aggregation while the tab was closed.
Opening the Agents tab briefly spikes during the panel expansion, then settles
at about 0.5%. The day's 17.8 MB of message JSON is no longer read on every
poll.

This release hides unavailable agents, fits the Agents panel to its content,
stops animated time labels from driving the notch's display link, removes the
repeated opencode message scan and fixes the per-day token total. It does not
change the opencode database schema, write to it, add settings keys, or change
how any agent is started or configured.
