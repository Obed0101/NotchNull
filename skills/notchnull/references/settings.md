# settings.json

`~/.notchnull/settings.json` holds every setting NotchNull has, grouped in sections. It is live
in both directions:

- Save the file and the notch changes within a moment, animated. No restart.
- Change something in the Settings window and the app rewrites the file (sorted keys, pretty printed).

The exact keys, types and ranges for the installed version are in
`~/.notchnull/settings.reference.md`, generated by the app on launch. Read it before editing;
do not rely on memory. `notchnull settings` prints the current values.

## Editing

- You can write only the keys you want to change; the rest keep their values. The app then
  rewrites the file with everything filled in.
- Or patch without touching the file: `notchnull settings set '{"look": {"accent": "#FF5E8A"}}'`.
  It exits non-zero and prints the errors if a value is rejected.
- Numbers outside their range are clamped. Unknown keys and wrong types are skipped and reported
  in `status.json` → `settingsErrors`, and in Settings › Build. One bad value never blocks the rest.
- Colors are `"#RRGGBB"` strings.

## Sections

| Section | Controls |
|---|---|
| `look` | Body material (`black`, `glass`, `tinted`), tint and accent colors, following the macOS accent, opacity, corner roundness, shadow, the light along the bottom edge, the glow when an agent needs the user, hiding the camera housing. |
| `size` | Extra width of the closed notch, wing scale, open panel width and height. |
| `motion` | Animation speed, spring bounce, hover delay to open, delay to close, cascading rows, open on `hover` or `click`. |
| `behavior` | Displays (`builtIn`, `main`, `all`), hiding the notch on a display while a fullscreen app covers it, the daily check for a new version, haptics, sounds, menu bar icon, hello lettering, usage pace warnings, remaining vs used, the Clipboard shortcut (`"ctrl+cmd+v"`, or `null`). |
| `features` | Each built-in feature on or off: music, HUD, tray, clipboard, screenshots, downloads, battery, devices, meetings, agents, Codex, Claude usage, mirror, stats. |
| `tabs` | `order` (every tab name, in order) and `hidden` (tab names). Tabs: `home`, `agents`, `controls`, `widgets`, `tray`, `downloads`, `clipboard`, `mirror`. `widgets` is hidden by default; remove it from `hidden` when the user wants panel widgets to show as a tab. |
| `home` | `rows`: which Home rows show, in order (`keepAwake`, `upNext`, `timer`, `system`, `agents`, `network`, `battery`, `storage`, `toggles`, `clipboard`), plus `widget:<id>` for a widget with a `home` block. Rows past the panel's height scroll. |
| `activities` | `disabled`: activities that never slide out of the notch (names in the reference). |
| `downloads` | Ask how long to keep each download, the highlighted stop, what happens when unanswered, the Finder Temporary tag, and remembered answers per extension (`{"dmg": "day"}`). |

## Recipes

Pink accent, glass body, snappier motion:

```json
{
  "look": { "body": "glass", "accent": "#FF5E8A", "accentFollowsMac": false },
  "motion": { "speed": 1.4, "bounce": 0.1 }
}
```

Widgets first, no Mirror tab:

```json
{ "tabs": { "order": ["widgets", "home", "agents", "controls", "tray", "downloads", "clipboard", "mirror"], "hidden": ["mirror"] } }
```

Quiet notch (no volume or battery wings):

```json
{ "activities": { "disabled": ["volume", "brightness", "charging", "lowBattery"] } }
```

Check names against `settings.reference.md` first; the lists there are generated from the app.
After any edit, read `status.json` → `settingsErrors`, then render (`notchnull render /tmp/n.png --tab home`).
